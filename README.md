# Запуск

Нужен Go 1.27.1 или новее.

```bash
go run ./cmd/pos
```

Демонстрация «студент → критерии → оценки → итог → CSV»:

```bash
bash demo.sh
```

Скрипт получает итог **86/100**, сохраняет CSV и выводит путь к нему.

Меню позволяет создавать студентов и рубрикаторы, выставлять оценки и экспортировать итог. Если оценка уже есть, можно изменить, оставить или удалить её. При исправлении Enter сохраняет прежнее значение. Данные хранятся в памяти до выхода.

# Архитектура

Используется **Onion Architecture**:

* `internal/domain` — модель, инварианты и расчёт итога.
* `internal/application` — сценарии и порты репозиториев и экспорта.
* `internal/infrastructure` — репозитории в памяти и CSV-экспортёр.
* `internal/cli` — консольный интерфейс.
* `internal/di` — сборка зависимостей; `cmd/pos` — запуск.

Зависимости направлены внутрь: **CLI / Infrastructure → Application → Domain**. Домен не зависит от консоли и файлов. Репозитории реализуют интерфейсы из Application.

# DDD

* **Ubiquitous Language:** `Student` — студент, `Criterion` — критерий, `Rubric` — рубрикатор, `Evaluation` — оценка, `Score` — балл.
* **Entity:** `Student` и `Rubric` имеют UUID. Одинаковые имена не делают их одной сущностью.
* **Value Object:** `Score` и `Criterion` определяются значениями полей, собственного ID не имеют.
* **Агрегаты:** `Rubric` содержит критерии, `EvaluationForm` — оценки студента и снимок рубрикатора. Ключ формы — пара `StudentID + RubricID`; оценки изменяются через форму.
* **Repository:** порты находятся в `internal/application/ports.go`, реализации — в `internal/infrastructure/memory`.
* **Domain Service:** `EvaluationService` рассчитывает итог по оценкам завершённой формы.

Инварианты: балл от 0 до максимума критерия, критерий есть в рубрикаторе, одна оценка на критерий. Имена критериев уникальны внутри рубрикатора, сумма весов — 100%. Завершить форму можно после заполнения всех критериев; для исправлений её нужно вернуть в `Draft`.

Итог: **Σ(балл / максимум × вес)**, шкала 0–100. После суммирования результат округляется до сотых. В консоли и CSV используется один расчёт.

# Паттерны GoF

## Builder — порождающий

`application.RubricBuilder` пошагово собирает рубрикатор. Ошибочный критерий можно ввести повторно, сохранив предыдущие. `Build` проверяет готовый рубрикатор перед сохранением.

## Facade — структурный

`application.Facade` объединяет сценарии четырёх сервисов. CLI получает одну точку доступа и не знает, как сценарии распределены между сервисами.

## Strategy — поведенческий

`domain.ScorePolicy` задаёт правило округления итога: `ExactScorePolicy` сохраняет точность, `HundredthsScorePolicy` округляет до сотых. Стратегию выбирает DI-контейнер; формула расчёта не меняется.

# Dependency Injection

Собственный контейнер `internal/di/container.go` связывает порты с адаптерами и собирает сервисы и фасад. Через `sync.OnceValue` зависимости создаются один раз на контейнер. В сервисы они передаются через конструкторы.


Юнит-тесты проверяют инварианты, расчёт итога, Builder, сервисы и адаптеры. В тестах Application репозитории заменены тестовыми реализациями. В `tests/integration` проверяется связка CLI, сервисов, репозиториев и CSV-экспортёра.
